# 骨牌造境 · Chainline

骨牌连锁的构筑、模拟与**能量回放**工作台。

## 本地启动

```sh
npm ci
npm run dev
```

在浏览器打开 Vite 输出的本地地址。

## Docker 启动

```sh
docker compose up --build
```

打开 <http://localhost:8032>。端口可通过 `DOMINO_LAB_PORT` 修改。

## 能量收支

模拟时除了倒下顺序，还会按事件记录一份能量账：

- **输入**：摆锤储能（外部输入），以及每个部件自身重心下降释放的重力势能 `m·g·h/2`。
- **去向**：枢轴/底面摩擦、各条接触（相邻、机关连线、摆锤冲击、坡面释放）的界面损耗、坡道暂存的势能、以及未再传递的残留。
- **来源**：每一焦耳都带着来源标签（摆锤 / 重力 / 坡道）与上游流水号，可在回放面板中逐级“追溯来源链”回到摆锤输入那一行。

几条关键约定：

1. **总量守恒 ≠ 单次接触足以触发。** 收支平衡校验的是整场回放：`输入 = 接触损耗 + 摩擦 + 残留 + 滞留/在途`。每次到达另有一条“触发判定”，把本次到达与触发门槛 `门槛 = m·g·h/2 × 0.35 × fallThreshold/0.8` 对比，判定本次接触是否足够。
2. **同一份输入不会完整记在两条支路上。** 分岔枢纽把可用能量按支路数均分，每条支路各记 `1/n` 份额，并附带接触损耗；两支路之和恰好等于枢纽的可用能量池。同一刻到达多个支路时，会先合并成一个能量池再判定与再分配。
3. **坡道让势能滞后参与传播。** 坡道先记“坡道储能”，`0.45 s` 后才以“坡道释能”重新进入链路；在释能之前，这部分能量不计入下游，也不计入损耗。
4. **不足门槛的能量记为滞留**，不回填成损耗；后续接触补足后会并入同一能量池，若到结束仍不足，则作为“滞留”进入收支并在该部件中断链路。

## 验证场景

顶栏“验证场景”可切换到 **能量验证 · 摆锤分岔**：

> 摆锤 → 传导牌 → 储能坡（先储后放）→ 坡顶枢纽（双支路、同延迟）→ 左右两臂同刻触碰合流牌 → 尾牌 → 无可触达元件而中断。

运行后右侧“能量收支”面板可核对：

- 摆锤输入 96 J，收支徽章显示“收支平衡”；
- 储能坡在 0.48 s 存、0.93 s 释；
- 双支路各记 50% 份额，合流牌收到两路合并后的能量池；
- 尾牌因耗尽可触达方向而中断，整场差额为 0。
